# M24 repair and one live rule

A bad first idea fails its type check. A good second idea passes.
The page changes once, on the final KEEP. Then the sentence `tab 4`
swaps the live rule. A bad rule is healed, and SAY still shows 4.

```bash
bash scripts/smoke_m24.sh
```

The script runs the native Aura binary. It does not call docker.
It does not bump the Aura commit. The binary stays the Release
build of Aura `0f93a31ed`. Emacs timing runs with `PAD_SENTENCE`
unset and must print `PAD_PERF_EMACS_OK`. The classic pty check
sets `PAD_CLASSIC=1` only for the old open, new, unsaved,
emergency, and vi scenarios. Each of those prints `CLI_PTY_OK`.
The script prints `PAD_FX_DEC_OK`, `PAD_TX_FIX_OK`,
`PAD_NO_EVAL_OK`, `PAD_RULE_OK`, `PAD_LAZY_RULE_OK`,
`PAD_PERF_EMACS_OK`, and `PAD_M24_OK`.

## Hands-on

The repair page starts as `(define (hello x) (+ x 1))`. The first
idea is `hello=(lambda (x) (string-append x 1))`. That idea fails.
SAY shows `try 1` from `intend-history`. The second idea is
`hello=(lambda (x) (* x 2))`. That idea passes. SAY shows `try 2`.
The page changes once. The bad body is not written. `(hello 3)`
is 6.

Then `tab 4`. The sentence calls `pad:kr-cmd!`. SAY contains 4.
The indent rule is 4 spaces. One swap is logged with a millisecond
timestamp.

Then `tab 40`. That number is out of range. The bad body is healed.
SAY is `heal, tab jumps 4 spaces`. The live value is still 4.

Arrow keys do not load the rule file or the intend file. After
those keys, `set_code` is still 0. The first `tab 4` loads the
rule. The first repair loads the intend file.

The verifier does not eval a generated closure.

## What this step does not do

It does not update `docs/tutorial.md`. It does not bump the Aura
commit. It does not call a live model. It does not add an `M-x`
verb.
