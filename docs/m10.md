# M10: who wrote this + engine dirty cross-check

M10 answers the kid's question "who wrote this line?" (ctrl-o, byte 15)
and checks, after every pen KEEP and every check, that the rows the
engine reports dirty are rows the Soft frame already marked DIRTY (or the
cursor row). Soft owns all of it; C is unchanged. Soft tip: `c69e644`.

```bash
bash scripts/smoke_m10.sh            # M10_ACC 1..4 OK, PAD_M10_TEST_OK, PLAY_WHO_OK, PAD_M10_OK
PAD_LIVE=0 bash scripts/smoke.sh     # M0..M10 → PAD_SMOKE_OK
```

## Stamps

A stamp is `#f` (nobody changed the row since the page was opened) or
`(who why gen)`: `who` ∈ kid / helper / macro / law, `why` the reason the
writer gave (the pen's `why`; `typed` for the kid), `gen` the workspace
generation after the write (`engine:metrics "ast:generation"` via
`pad:pen-gen`, because bare `ast:generation` is unbound on tip, #4349; kid
stamps carry the last generation the pad read).

Stamps follow the page by **row identity** (`eq?`), the same way the M7
line cache follows rows: editor commands and the pen projection keep
every untouched row object, so a row whose object changed was written by
whoever wrote since the last sync. A row matches the old row at the same
index, or at the index shifted by the row-count change (splits and joins).

Sync points are rare, so the key path pays nothing per key:

- before a pen step (`kid`: anything the kid typed since the last sync),
- after a KEEP (`who why gen` of the pen, on the rows the KEEP projected),
- after a pen undo,
- when the kid presses ctrl-o (`kid`).

Between sync points only the kid writes, so attributing every changed row
to the kid is exact. A row that **comes back** gets the stamp it had in
the snapshot it came back from: `*who-hist*` keeps `(L . stamps)` for the
last 32 page objects. An exact page match (editor undo restores the very
`L` object it saved; pen undo restores the pre-KEEP `L`) takes the whole
snapshot; otherwise each unmatched row is looked up in the snapshots.

ctrl-o answers for the cursor row:

| stamp | machine line (tests) | SAY (kid) |
|-------|----------------------|-----------|
| `#f` | `no-who` | nobody has changed this yet |
| kid | `WHO who=kid why=typed gen=G` | you wrote this line |
| helper | `WHO who=helper why=closer gen=G` | the AI helper wrote this line: closer |
| macro / law | `WHO who=macro why=swap gen=G` | a macro wrote this line: swap |

In `play.aura` ctrl-o is a cursor-only frame (text unchanged). SAY is the
last message, as before M10: the answer stays on the SAY line until
another command sets one (plain typing does not).

## Pen stamps and undo

`pad:who-pen-step! who name lam why` syncs `kid`, remembers `query:code`,
runs `pad:pen-step!` (M9: REJECT / KEEP / DROP + heal), and on KEEP
re-reads the generation and stamps the projected row. It returns
`(pen-result rows-stamped)`. A KEEP whose row cannot be projected
(`multi-line`, `too-wide`) leaves the page object as it is, so nothing is
stamped. The engine changed but the page row did not; the next check
reconciles it (M9 behaviour).

`pad:who-pen-undo!` runs `pad:pen-undo!` (`ast:restore` of the snapshot
taken before the KEEP, then one heal `eval-current`, #4349), syncs, and
re-projects (`pad:ws-project`). It answers `agree` only if all four hold:

- the page is the very `L` object the Soft undo entry saved,
- `query:code` equals the code before the KEEP,
- the generation equals the one before the KEEP,
- the restored workspace still projects the checked page (`*ws-L*`).

Anything else prints `M10_UNDO_DISAGREE page=… code=… gen=… proj=…` and
answers `disagree`. The test plants one wrong saved code
(`K3_PLANTED=disagree`) to prove the check can fail. The smoke requires
exactly that one disagreement line and no other.

## Engine dirty cross-check

`query:dirty-nodes` **is bound** on `c69e644`
(`src/compiler/evaluator_primitives_compile.cpp`). It takes one reason
(general, constraint, occurrence, ownership, coercion, struct, defuse,
ppa-hint) and returns node-id strings. The pad takes the union over all
eight reasons. c69e644 has no node → row (or node → parent) query, so
nodes are placed on rows through the page's own defines:

- the Soft find-defs row of each page define,
- `query:defines name` (bound) → define node ids,
- `query:dirty-subtree id` (bound) → count of dirty nodes under that define.

Engine dirty bits stay set until the next check reloads the workspace,
while a Soft DIRTY line covers one frame. So each cross-check compares
only what **became** dirty since the previous cross-check point (a check
via `pad:who-check!`, or the previous `pad:who-xdirty`): defines whose
dirty count grew, and node ids not seen before. Those rows must be a
subset of the frame's DIRTY rows plus the cursor row. A frame without a
DIRTY line is a full blit, so every row counts as dirty.

From the test, on the 12-row M9 pen page:

```
XDIRTY at=check verdict=ok engine=none soft=0 cursor=0 since_check=none dirty_nodes=0 new_nodes=0 unmapped=0
XDIRTY at=keep-hello verdict=ok engine=0 soft=0 cursor=0 since_check=0 dirty_nodes=2 new_nodes=2 unmapped=1
GAPS query:node-row unmapped=1
XDIRTY at=keep-add verdict=ok engine=2 soft=2.5 cursor=5 since_check=0.2 dirty_nodes=3 new_nodes=1 unmapped=0
XDIRTY at=check verdict=ok engine=none soft=2 cursor=2 since_check=none dirty_nodes=0 new_nodes=0 unmapped=0
```

What the engine reports today:

- A `mutate:rebind` KEEP marks the rebound define dirty (reason
  `general`). Callers are not marked (`bye` calls `hello` and stays
  clean), so on this page the engine set is narrower than "everything
  that depends on it".
- The hello rebind leaves one more dirty node that is not under any page
  define's subtree. The pad does not guess a row for it: it is counted as
  `unmapped` and printed as `GAPS query:node-row unmapped=1`. That is the
  honest limit of placing nodes without a node → position query.
- A check (`set-code` + `eval-current`) reloads the workspace and the
  dirty set is empty afterwards.

Unbound `query:dirty-nodes` would give verdict `gap` and a
`GAPS query:dirty-nodes` line, with Soft DIRTY the only source. The test
simulates that path once (`GAP_PATH=gap`), and the smoke requires exactly
one such line. `MISS_DETECT` / `GROWN_ONLY` show the subset and delta
helpers are not vacuous. The smoke fails on any real `verdict=miss`.

## Not done / limits

- Stamps are row-level, not character spans: a row has one writer, the
  last one.
- `play.aura` has no pen (M9 is notebook-only), so in the live pad every
  stamp is `kid` or nobody. Helper / macro / law stamps come from
  `pad:who-pen-step!` in the notebook handler and the tests.
- The engine side of authorship (`query:node-provenance` /
  `query:last-mutation-provenance` both return hashes on tip) is not read
  yet. The stamps are the pad's own record.
- Soft scoping on c69e644: an outer local captured inside a named-let
  body can resolve to a same-named global (found during the latency
  work; Aura #4353). `who*.aura` loops
  are top-level functions with their data as parameters, and test
  globals carry an `m10` prefix.
