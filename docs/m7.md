# M7: snappy pad — line-incremental Soft key path

M7 makes a key cost **O(edited line)** instead of **O(page)**. Soft still
owns every decision; C is byte-for-byte unchanged. Requirements and
budget: [`REQUIREMENTS.md`](REQUIREMENTS.md) §5, [`DESIGN.md`](DESIGN.md)
§8, numbers in [`perf.md`](perf.md).

```bash
bash scripts/smoke_m7.sh             # PAD_M7_TEST_OK, PAD_M7_DIRTY_OK, PAD_PERF_OK, PAD_M7_PERF_OK, PAD_M7_OK
bash scripts/smoke_perf.sh           # perf only (one retry on wall-clock noise, reported)
PAD_LIVE=0 bash scripts/smoke.sh     # M0..M7 → PAD_SMOKE_OK
bash scripts/build_c.sh && ./out/c/pad_play   # same kid pad, faster keys
```

## Why

At tip `648ae08` the two-row play page measured insert ~41–49 ms / cursor
~21–29 ms per key (gate 50 ms — flaky: 54 ms under load), and a
twelve-row page ~234 ms per insert: every text change re-tokenized the
whole page (~1 ms per char at the Soft floor) and every name change
re-marked the whole page.

## What shipped

| piece | file | what |
|-------|------|------|
| line tokenizer | `soft/pad/lc.aura` `pad:lc-line-toks` | mirrors `pad:hl-one`, char classes from a 128-slot vector built from the M5 predicates; reports `open` when a string runs off the line |
| line cache | `lc.aura` `pad:lc-frame!` | per line `(codes str toks tape open last1 last2 syms)` + record `(entry mkey mrow p1 p2)`; *move*, *one-line edit*, *generic*, *full fallback* frames (DESIGN §8) |
| exact DIRTY | `lc.aura` `pad:lc-dirty` / `pad:lc-remark!` | sorted rows whose T/H/M changed + cursor row; omitted on the first frame |
| jump from cache | `pad:lc-toks`, `jump.aura` `pad:goto-def-in` / `pad:find-refs-cmd-in` | ctrl-g / ctrl-r reuse cached tokens (offset-shifted) instead of re-tokenizing |
| key wiring | `keys.aura` `pad:play-snap` | now `pad:lc-snap`; the M6 path stays as `pad:play-snap-m6` (perf "before") |
| builtin list helpers | `buffer.aura` `pad:take` / `pad:drop`, `lines.aura` `pad:nth` | `length` / `reverse` / `list-tail` / `list-ref`: same results, one Soft call instead of n; gate+apply 12 → 6 ms |
| perf | `soft/pad/perf.aura` | small page + twelve-row page, M6 vs M7, cmd-only, `PERF_FLOOR` |
| tests | `soft/pad/m7_test.aura` | 147 checks; every frame diffed against `pad:snap-text` |
| host audit | `scripts/dirty_check.py` | DIRTY sound + tight on a Soft play stream |

## Exactness

Per-line tokenize equals whole-page tokenize unless a token crosses a
newline; in this tokenizer only an unclosed string can (comments end at
newline; numbers check the previous char, and a newline is a space). A
line with `open` sends that frame down the M6 whole-page path, so the
bytes stay identical; the next frame without an open string is fast
again. `m7_test.aura` checks:

- `TOK_EQ_*` / `COLOR_EQ_*`: 12 tricky lines (escapes, `query:`/
  `mutate:`, `"cat"123`, `#t 'x`, empty, spaces, UTF-8) — line tokens and
  token-sliced tape equal the M5 ones.
- `FRAME_*`: each key frame (DIRTY line removed) equals
  `pad:snap-text title L line col say` — the M6 key script, a 12-row
  script (type, refused enter on a full page, join, split, kill / yank /
  undo, cursor onto `hello`, ctrl-g / ctrl-r / ctrl-b, open + close a
  string), and a 79-char line (per-char fallbacks).
- Counters: one insert = one line re-tokenized (`BIG_RETOK_TYPE=15` after
  12 + 3), a split = two (`BIG_RETOK_SPLIT=2`), cursor moves = zero.
- DIRTY: `BIG_SP_DIRTY=6`, `BIG_MARKS_DIRTY=0,1,6,10,11` (cursor walks
  onto `hello`), `BIG_MARKS_SAME=0` (still on `hello`), `DIRTY_EOB=11`.

## Numbers (tip binary `73c012c`, `dev:v1.0.9`)

| page | path | insert ms/key | cursor ms/key |
|------|------|---------------|---------------|
| 2 rows | M6 tip `648ae08` | ~41–49 | ~21–29 |
| 2 rows | M7 | ~23 | ~12 |
| 12 rows | M6 tip `648ae08` | ~234 | ~45 |
| 12 rows | M6 path (same run) | ~223–234 | ~40 |
| 12 rows | M7 | ~26–30 | ~13 |

Cursor is now under one 60 fps frame; insert is not (Soft floor:
~0.2 ms/call, Aura #4343; in-place `vector-set!` ~15 ms, which is why
`lc.aura` never mutates a vector — it rebuilds with `list->vector`).

## KEEP / DROP

KEEP: per-line cache with an oracle diff on every frame; exact DIRTY with
a host audit; builtin list helpers; honest fallback for multi-line
strings; C untouched. DROP: in-place vector updates (slower on tip than
rebuilding), a C-side row diff as the source of truth (Soft decides),
claiming vi/Emacs speed.

## 中文

M7「快手 pad」：每键只重新分词**被编辑的那一行**，不再整页重来。逐行
缓存 token / 高亮色带 / 标记行 / 行字符串；光标移动若名字没变只标脏光
标行，名字变了只重画含新旧名字的行；回车、合并、粘贴、撤销用代码表
匹配旧行（位移 d/0/−1/+1），能复用就复用；有跨行未闭合字符串时整帧退
回 M6 全量路径，保证字节完全一致。`DIRTY` 现在精确等于「T/H/M 变了的
行 + 光标行」，由 `dirty_check.py` 审计。`pad:take`/`pad:drop`/`pad:nth`
改用内建函数。147 项 Soft 测试逐帧与全量 `pad:snap-text` 对拍。12 行页
面插入 ~230 → ~26–30 ms，光标 ~40 → ~13 ms；两行页面 49/29 → 23/12 ms。
C 一行没改。光标已低于一帧，插入还没有——下限是 Soft 解释器（#4343，
以及原地 `vector-set!` 很慢的新发现）。
