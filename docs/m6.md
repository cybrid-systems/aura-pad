# M6: thin C viewport (加c) — Soft owns the editor, C only blits

M6 adds a **thin C viewport** to Aura Pad. Soft still owns everything that
makes it an editor: the buffer, the cursor, every gate and kid REJECT
reason, the keymap, the HL tape (M5 `hl.aura`), the goto-def / find-refs
marks (M5 `jump.aura`) and every word a kid reads. Soft packs those
decisions into a blit-friendly **SNAP block**; C reads the block and
paints it with ANSI colors (or plain text for CI). C never tokenizes,
never gates, never edits, never maps a key.

M0–M5 files and numbers are unchanged. All M6 work is new files plus one
`smoke.sh` line.

```bash
bash scripts/smoke_c.sh              # PAD_M6_TEST_OK, PAD_M6_OK, PAD_M6_MODEL_OK, PAD_C_THIN_OK … PAD_C_OK
PAD_LIVE=0 bash scripts/smoke.sh     # M0..M6 → PAD_SMOKE_OK (no MiniMax)
bash scripts/build_c.sh && ./out/c/pad_play   # interactive kid pad (needs a terminal)
```

## Viewport role (the one rule)

| who | owns |
|-----|------|
| **Soft** (`view.aura`, `keys.aura`, `play.aura` + M3–M5 files) | buffer, cursor, gate, undo/yank/mark, keymap (bytes → commands), HL letters, def/use marks, jump stack, title, SAY, LEGEND words |
| **C** (`c/snap.c`, `c/pad_view.c`, `c/pad_play.c`) | read SNAP lines, check shape, map letter → color, draw, forward raw key bytes |

`scripts/smoke_c.sh` enforces it (`PAD_C_THIN_OK`): the C sources may not
contain editor command words (`"left"`, `"undo"`, `"goto-def"`, …), HL
keywords (`"define"`, `"query:"`, …), kid words (`born`, `jump`, …), and
`pad_play.c` may not compare a key byte. If C ever needs to know what a
key or a word means, that logic belongs in Soft.

## SNAP wire (`soft/pad/view.aura`)

Same `SNAP v1 … END` family as aura-parkour / aura-tetris, with a `pad`
tag:

```
SNAP v1 pad
TITLE kid pad (Soft)
CURSOR line=2 col=1
SAY there is no line there
LEGEND K=magic-word S=name T=quote C=note N=number P=paren Q=ask M=change d=born-here r=used-here
ROWS n=3
T (define (hello x) (+ x 1)) ; hi
H PKKKKKK.PSSSSS.SP.PS.S.NPP.CCCC
M .........ddddd.................
T (define (bye y) (hello y))
H PKKKKKK.PSSS.SP.PSSSSS.SPP
M .................rrrrr....
T (hello 3)
H PSSSSS.NP
M .rrrrr...
END
```

- `T` row text, `H` M5 HL tape slice, `M` mark tape slice; `|T| = |H| = |M|`.
- HL letters: `P K S T C Q M N .` (M5). Mark letters: `d` the name under
  the cursor is born here (def), `r` it is used here, `.` none.
- `CURSOR` is 0-based `(line col)`; `col` may equal the row length (end of line).
- `LEGEND` words are Soft's; C only colors each `X=word` with letter `X`.
- Soft writes a block to a file (`pad:snap-write!`, `write-file`) or to
  stdout (`pad:snap-emit!`). A stream may carry many blocks mixed with
  Soft log lines; C skips non-SNAP lines and **the last complete block wins**.
- **Fail closed**: a block with a bad line, wrong lengths, an unknown
  letter, an out-of-range cursor or no `END` is dropped whole. No accepted
  block → `pad_view` exits 1 and draws nothing. A truncated tail keeps the
  last accepted block.

## C programs

- `pad_view [--ansi|--plain] [--stats] [file|-]` — blit one snapshot (file
  or stdin stream) and exit. Default ANSI on a TTY unless `NO_COLOR`;
  `--plain` draws a caret line under the cursor and the mark tape under
  marked rows (deterministic golden for CI). `--stats` prints
  `PAD_C_BLIT rows= cells= cursor= marks= snaps= rejected= mode=` on stderr.
- `pad_play [--ansi|--plain] [--final] [--stats] [soft_play.sh]` — spawns
  `scripts/soft_play.sh` (Soft `play.aura` in the dev image), puts the
  terminal in raw mode, forwards every key byte as `IN <byte>` and blits
  each SNAP Soft sends back. `ctrl-q` quits only because Soft's keymap says
  so (Soft exits, C sees EOF). `--final` draws only the last frame (headless).
- ANSI palette: magic word bold magenta, quote green, note dim, number
  yellow, paren cyan, `query:` bold blue, `mutate:` bold red; `d` bold
  underline, `r` underline, cursor reverse video. One SGR per run.
- Build: `scripts/build_c.sh` (host `cc`, `-std=c11 -Wall -Wextra -pedantic
  -Werror`) → `out/c/`. `PAD_C_DOCKER=1` builds and runs inside
  `ghcr.io/cybrid-systems/dev:v1.0.9`; `PAD_C_ASAN=1` adds ASan/UBSan.
  `c/CMakeLists.txt` builds the same two targets. No SDL/X11 needed (the
  dev image has X11 headers but no SDL2; ANSI first so smoke stays headless).

## Soft play (`soft/pad/keys.aura`, `soft/pad/play.aura`)

stdin lines: `IN <byte>` (raw key from C), `KEY <word>` (scripted),
`QUIT`. stdout: SNAP blocks only. Soft keymap:

| key | Soft command |
|-----|--------------|
| printable | type it (viewport pad allows any printable; line max 40) |
| arrows (`ESC [ A/B/C/D`) | `prev-line` / `next-line` / `right` / `left` |
| ctrl-a / ctrl-e | `home` / `end` |
| backspace | `back` |
| enter | `open-line` then `right` (new line) |
| ctrl-k / ctrl-y | `kill-line` / `yank` |
| ctrl-space / ctrl-w / ctrl-p | `set-mark` / `kill-region` / `copy-region` |
| ctrl-_ / ctrl-u | `undo` |
| ctrl-g | goto-def ("jumped to where hello is born") |
| ctrl-r | find-refs ("hello is used 2 times") |
| ctrl-b | jump-back |
| ctrl-q | quit |
| anything else | REJECT "that key does nothing yet" |

Every command goes through the M3.5 Soft gate (`pad:egate`) or the M5 jump
commands; a rejected key never changes the buffer and only changes SAY.

## Smoke (`scripts/smoke_c.sh`)

1. `PAREN_OK` on the new Soft files.
2. `m6_test.aura` — 61 Soft checks (split / point / line-col clamp / marks
   / exact SNAP text / keymap escape state / play gate + jump + undo +
   enter) → `PAD_M6_TEST_OK`.
3. `m6_smoke.aura` — Soft plays `eob home right next-line` (the last is a
   kid REJECT `no-line`), writes `out/m6.snap`, emits it plus a second block
   after Soft goto-def → `PAD_M6_OK`.
4. `snap_model.py --check` rebuilds `out/m6.snap` byte for byte from the
   M5 host HL/jump model → `PAD_M6_MODEL_OK`; it must also equal
   `c/fixtures/good.snap`.
5. Build C; `PAD_C_THIN_OK` guard.
6. `pad_view` file blit equals `c/fixtures/good.plain` and
   `good.ansi.txt` (ESC kept as `\e`);
   the Soft stdout stream keeps the last block (`cursor=0:9 snaps=2`);
   `truncated`/`badlen`/`badcursor`/`badletter`/`noise` exit 1 and draw
   nothing; `tail.snap` keeps the last good block (`rejected=1`).
7. `soft_play.sh` gets 17 scripted key bytes, its SNAP stream is blitted by
   `pad_view` (`(hello 4)`, cursor `1:1`, 13 snaps); then `pad_play --final`
   drives the same Soft child with the same raw bytes and must draw the
   identical frame (host build; skipped as `PAD_C_PLAY_SKIP` under
   `PAD_C_DOCKER=1`, no nested docker).
8. `PAD_C_OK`.

Each key costs about 0.15 s of Soft work (HL + marks re-pack the whole
buffer); fine for a kid pad, not tuned.

## KEEP / DROP

KEEP: Soft decides, C paints; one wire shared with the sibling games;
fail-closed reader; golden blits; a guard that keeps C thin. DROP: a C
lexer, a C keymap, C-side cursor math, SDL/X11 before the ANSI path is
proven headless.

## 中文

M6 “加c”：给 Aura Pad 加一个**很薄的 C 画面**。

- **Soft 做所有决定**：缓冲区、光标、门卫和小朋友拒绝理由、按键表（字节
  → 命令）、M5 的高亮色带、goto-def / find-refs 标记（`d` 出生的地方、
  `r` 用到的地方）、跳转栈、标题、SAY 提示和图例文字。
- **C 只负责画**：读 Soft 写出的 `SNAP v1 pad … END` 块，检查形状，把字母
  映射成颜色画到终端（ANSI，CI 里用 `--plain` 纯文本）；`pad_play` 只把
  原始按键字节 `IN <byte>` 转发给 Soft，按什么键做什么由 Soft 决定，
  ctrl-q 退出也是 Soft 说了算。
- 坏块、长度不对、未知字母、光标越界、没有 `END` 的块整块丢弃；一个都
  没有就退出 1、什么也不画（fail closed）；流里最后一个完整块获胜。
- `scripts/smoke_c.sh`：61 项 Soft 测试、Soft 快照 + Python 模型逐字节对拍、
  C 构建、`PAD_C_THIN_OK`（C 源码里不许出现编辑命令词 / 关键字 / 小朋友
  提示词，`pad_play.c` 不许比较按键字节）、黄金画面对比、失败关闭、
  soft_play 脚本按键 → Soft → SNAP 流 → C 画面，最后 `PAD_C_OK`。
  `PAD_LIVE=0 bash scripts/smoke.sh` 仍以 `PAD_SMOKE_OK` 结束。
- 交互：`bash scripts/build_c.sh && ./out/c/pad_play`（需要终端；
  方向键移动，ctrl-g 找名字在哪里出生，ctrl-b 跳回，ctrl-q 再见）。
