# M11d — Aura-unique features

Part of [M11](m11.md). Soft tip `c69e644`.

## M11d — "blast radius" card before KEEP (`soft/pad/blast.aura`, `PAD_M11_BLAST_OK`)

**What the kid sees.** With the card path (`pad:robot-card!`), a helper
idea does not land right away. The say line shows what it would move,
and the page stays as it is:

> changing add moves 3 places: greet, (greet (add 1 2)), (add 2 3). enter keeps, ctrl-z says no

**Enter** keeps it, exactly like an M11a KEEP: rows projected, a ctrl-z
undo entry, "who" stamps. **ctrl-z** says no: "ok, the helper's idea is
gone, nothing changed". A proposal aura refuses never shows a card; the
kid gets the M11c reason instead.

**How.**
1. The proposal goes through the same gate and the same one
   `typed-mutate-atomic` inside an `ast:snapshot` (M11a). On `#t` it
   *waits* (`*robot-pending*`): the engine has the change, the page does
   not.
2. Soft builds the page the KEEP would give (`pad:pen-project`). It
   finds every call site of the changed names, meaning a name right
   after `(` that is not a define head, and drops the changed defines'
   own rows. Each remaining row is named by the define it starts, by its
   text when short, or as "line N". At most 3 are shown, then "and N
   more".
3. The engine checks that answer:
   - `query:calls name` must find as many call sites as Soft did, per
     name. After a rebind the engine also keeps the replaced body's
     sites (aura#4364, filed). In that case the engine must have added
     exactly the call sites the new bodies hold. The counts are taken
     before and after the transaction: `sites=hello:3/4:+1` means Soft
     finds 3, the engine says 4 (stale), and the engine added 1, which
     is the `(hello y)` in the new `bye`;
   - per page define, `query:defines name` plus `query:dirty-subtree`,
     before and after the transaction. The defines whose dirty count
     grew must be changed names, and every changed name must be dirty
     now. After a rebind, `query:dirty-nodes` marks only the rebound
     define node and the root (probe `p11`), so callers never show up
     as dirty.
   - A mismatch prints `M11_BLAST_DISAGREE` and fails the smoke.
4. Enter calls `pad:robot-commit!`, the same code as an M11a KEEP.
   ctrl-z calls `ast:restore` + `eval-current`. One heal, and nothing is
   pushed for undo.

**Measured on the tip.**
- `BLAST names=hello.bye uses=6.7.11 sites=hello:3/4:+1.bye:2/2:+0 grown=hello.bye dirty=hello.bye verdict=agree`.
- While the card waits, the page object is unchanged (`D1_PAGE_WAITS`)
  and `query:code` already has the change (`D1_ENGINE_HAS_IT`).

**Limits.** c69e644 has no node → row query, so the rows come from
Soft and the engine confirms the counts. `query:reaches` (def-use) and
`query:calls` give node ids, not rows. Like every robot path, the card
lives on the notebook face, not in `play.aura`, so key latency is
unchanged.
