# M11c — Aura-unique features

Part of [M11](m11.md). Soft tip `c69e644`.

## M11c — "why did it break?" in kid words (`soft/pad/why.aura`, `PAD_M11_WHY_OK`)

**What the kid sees.** When aura refuses a helper's change, the say line
names the define that broke and says why in one short sentence, instead
of a bare "no":

| aura's own reason (c69e644) | say line |
|---|---|
| `type error: argument 1: expected String, got Int` in the new body | the helper's greet used a number where words go |
| `arity mismatch: call 'hello': expected 1 arguments, got 2` in the new body | the helper's bye gives hello 2 things, it wants 1 |
| the same, blamed on a line that *uses* the changed define | the helper's hello now wants 2 things, but bye gives it 1 |
| `type error … blamed: caller` on `(bye 4)` | the helper's bye does not fit (bye 4) |
| `unbound variable: frob` | the helper's bye uses frob, nothing is called that yet |
| `parse-error … unexpected ')'` | the helper's bye has a bracket in the wrong place |
| a missing `)` (the engine closes it silently, probe `p8`) | the helper's brackets do not match (Soft gate, before any snapshot) |

**How.**
1. `typed-mutate-atomic` answers only `#f`. So after a refusal, *before*
   the robot's heal, `pad:why-probe!` replays the proposal one
   `mutate:rebind` at a time. The first refusal gives aura's text. The
   replay can commit the good edits ahead of the bad one, but the
   robot's single `ast:restore` + `eval-current` puts them back. Tests
   check one heal per refusal, unchanged code and page, and that
   notebook procedures still answer.
2. A Soft table turns the text into a sentence:
   - it finds the kind (arity / type / unbound / brackets);
   - it reads the names and numbers out of the text;
   - it maps type names to kid words (String → words, Int → a number,
     a type variable → something else).
   If the 1-based line after `(selective) failed:` holds a call to the
   changed define and is not that define's own row, aura is blaming a
   caller. The sentence then names that line: the define it starts, the
   row text if it is short, otherwise "line N".
3. After a KEEP, `typecheck-incremental` lines go through the same
   table. On the tip they only show up as "aura warns: …" when they are
   real.
   - `unbound variable: X` is dropped when `X` is a notebook define.
     `typecheck-incremental` reports value defines like `pet` as
     unbound, and after a refused rebind it still shows diagnostics from
     the refused body. Filed as
     [aura#4363](https://github.com/cybrid-systems/aura/issues/4363).
   - `C3_TC_SAID_PET` checks that the false line really came, and
     `C3_NO_FALSE_WARN` checks that the kid never saw it.

**Measured on the tip.**
- Every refusal in the tests gives the sentence in the table above
  (`C2_*`, `C3_CALLER_TYPE_SAY`).
- The replay costs one extra rebind per edit up to the bad one. It runs
  only on refusals, never on the key path.
