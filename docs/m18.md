# M18 performance

Step 20 publishes the sentence cursor before a check and after it.
The Emacs frame gate is unchanged.

```bash
bash scripts/smoke_m18.sh
```

The script runs the native Aura binary. It does not call docker.
Wall-clock noise gets one retry, the same rule as `scripts/smoke_perf.sh`.
A cursor that is not strictly under 16000 microseconds fails with that
script's sentence:

```text
PAD_PERF_EMACS_FAIL (over the 16 ms frame)
```

There is no gate that the cold cursor must be 1.3 ms or less.

## Cold cursor

`PAD_SENTENCE=1` and the read stack is not loaded yet. The arrow is
`pad:ux-move!`. It does not call `define-lookup`.

```text
PERF_READ cold_cursor_ms=<n>
```

`bash scripts/smoke_m18.sh` printed `cold_cursor_ms=0`
(`cold_cursor_us=689`) and `cold_lookup=0`. The millisecond line is
whole milliseconds.

## After a check

The check keeps the page tokens and the sentence for the cursor token.
The next arrow inside that token keeps the sentence and does not scan
the page again. It still does not call `define-lookup`.

```text
PERF_READ post_check_cursor_ms=<n>
```

`bash scripts/smoke_m18.sh` printed `post_check_cursor_ms=4`
(`post_check_cursor_us=4822`) and `post_lookup=0`. That is under one
16 ms frame, so the script does not print the failure sentence.
`check=checked`.

## Emacs frame without the sentence flag

`soft/pad/emacs_test.aura` still requires insert, cursor, the first
string open, and the close after it to be under 16000 microseconds.
This step does not change that comparison.

`bash scripts/smoke_m18.sh` ran that file with the flag unset.
It printed `EMACS_TEST checks=43 fail=0` and `PAD_PERF_EMACS_OK`.
Insert was `insert_us_key=1652`, cursor was `cursor_us_key=477`,
the first string open was `open_first_us=4000`, and the close after
it was `close_after_open_us=2833`.

The binary was `aura-grok/build-release/aura`, a Release build of
Aura `0f93a31ed`. The script prefers `build-release` when that tree
exists. A Debug `build/aura` of the same commit is slower than the
frame; the comparison in `emacs_test.aura` is unchanged.

## Hands-on

`aura-pad FILE` opens on the sentence line. Tab moves between the page
and that line. A letter typed on the page changes the projection. On
the line, `save` and `quit` are sentences, then Enter.

Open a file that contains an em dash. Press ctrl-e, type one letter,
Tab, `save`, Enter, `quit`, Enter. The letter is the only text
difference. The em dash is still its original UTF-8. A folded `-` in
its place would fail the byte compare.

Open that file again. Tab, then Enter on the empty line. `SAY` names
the birth line and the use count (`used 0` is allowed). Quit leaves
the bytes alone.

`PAD_CLASSIC=1 aura-pad FILE` is the old vi map: the frame shows
`[normal]`, and `i` (byte 105) enters insert. Direct `play.aura` with
no `PAD_SENTENCE` still shows the welcome card.
