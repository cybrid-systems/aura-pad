# M3 — multi-line buffer + command-helper propose

M3 adds a multi-line buffer that Soft owns, and lets a host (fixture file
or MiniMax) propose a **command helper**: a named Soft lambda that returns
a short command plan. Soft gates the body, probes the plan, races it
against the main helper on a two-line goal, and keeps it only when its
score is strictly higher. M0–M2 are unchanged; M3 only adds files.

```bash
bash scripts/smoke_m3.sh             # fixtures → PAD_M3_OK (+ live helper if keyed)
PAD_LIVE=0 bash scripts/smoke_m3.sh  # fixtures only, PAD_M3_LIVE_SKIP
bash scripts/smoke.sh                # M0+M1+M2+burn+M3 → PAD_SMOKE_OK
python3 scripts/propose_minimax.py --helper out/h.lambda 1 note  # one live helper
```

## Buffer (`soft/pad/lines.aura`)

- `*lines*` is a list of lines. Each line is a list of char codes (the M0
  shape, one list per line). The point is `(*line* *col*)`.
- Only `pad:stamp-lines!` writes these slots. Scoring (`pad:lsim`) is pure,
  so it is safe inside fibers.
- Start buffer: one line of 3 noise letters from seed `20261005` → `nwn`,
  point `(0,0)`. Goal: `"hi"` / `"aura"`.
- Distance: M0 per-line distance; a missing or extra line costs `len+1`.
  Start distance is 8.

| command | does | refused with |
|---------|------|--------------|
| char code / `"type:hi"` | insert at point | `not-print` (not a–z/space), `need-space` (line ≥ 12) |
| `left` / `right` | move, wrap across lines | `too-far` at the very start / end |
| `home` / `end` | start / end of line | — |
| `next-line` / `prev-line` | move a line, keep column (clamped) | `no-line` on last / first line |
| `open-line` | split at point, point stays (Emacs `C-o`) | `need-space` (4 lines max) |
| `kill-line` | kill to end of line; at end, pull next line up | `empty-buf`, `no-line` at end of last line |
| `back` | delete back; at column 0, join with line above | `empty-buf`, `too-far` at `(0,0)` |
| anything else | — | `not-a-key` |

`pad:open-line`, `pad:kill-line`, `pad:next-line`, `pad:prev-line` gate
first and return the reason string when refused, else `(lines line col)`.

## Command helper (`soft/pad/helper.aura`)

A helper body is `(lambda () (list TOKEN ...))`. Tokens are command words,
`"type:<text>"` (one key per letter), or char codes. At most 32 tokens and
48 keys.

Plan score = `40 - keys - 2*rejects - 3*dist` (fewer keys, no refusals,
closer to the goal).

Slots: `pd:helper` (trial) and `pd:hshadow` (main), both
`std/hot-strategy`. Flow per proposal:

1. `pd:helper-sync!` points both slots at the main helper body.
2. Gate the text: must start `(lambda`, and contain none of the M2 banned
   words (`set!`, `display`, `write`, `mutate`, `eval`, `load`, `shell`,
   `http`, `read-file`, `set-code`, `fiber:`, `hot-strategy`, …) nor
   `pd:helper`, `pd:hshadow`, `pad:stamp`, `pad:lsim`, `*lines*`,
   `string->symbol`, `require`, `import`, `define`.
   → `GATE reject reason=gate word=<w>`, `helper_reject`.
3. `hot-strategy:swap!` into `pd:helper`; probe the plan shape. Bad shape
   → `hot-strategy:heal!`, `HEAL ... reason=probe why=<not-a-plan|bad-token|too-long>`,
   `helper_heal`.
4. Plans are read outside fibers; two fibers run the pure scorer for main
   and trial (`pad:race-thunks!`). A host audit pass prints the trial's
   `REJECT mid=3 reason=.. cmd=..` lines.
5. `trial > base` → `KEEP`, the body becomes the main helper and its plan
   is stamped into `*lines*` (`TAPE ... text=hi|aura`). Otherwise
   `hot-strategy:heal!` + `DROP` (`lower-score-rollback` or
   `tie-is-not-better-rollback`).

`WORLD line=fiber_live` only when every spawned join returned a score and
`backend > 0`; otherwise `host-sequential`.

cross-checked against a Python model of the same rules.

## Live (MiniMax-M3, measured 2026-10-05)

`propose_minimax.py --helper` asks for one helper line, pre-checks the
shape (known command words / `type:[a-z ]*` / digits, ≤ 32 tokens) and the
banned words, and writes the file. Soft does the real gate.

- Run 1: `"type:h" "type:i" "kill-line" "kill-line" "open-line" "next-line" "type:aura"`
  → one `REJECT reason=no-line cmd=kill-line`, `RACE helper base=27 trial=29`,
  `KEEP`, `TAPE text=hi|aura`. `PAD_M3_LIVE_OK`.
- Run 2 (full `smoke.sh`): an 11-token helper that leaves an extra line →
  `RACE helper base=27 trial=-2`, `DROP lower-score-rollback`, heal.
  `PAD_M3_LIVE_OK`.

Any honest tag (`helper_keep`/`drop`/`heal`/`reject`) is live success. HTTP
failure or a Soft error is `PAD_M3_LIVE_FAIL`.

## Note on `load`

An unbalanced `)` in a `load`ed file made the tip binary silently stop
reading that file (and rerun the top-level forms) instead of reporting a
parse error. If definitions from a loaded file look unbound, check the
paren balance first.

## 中文

M3：缓冲区变成多行（每行一串字符码），光标是（行，列）。新增行命令：
`open-line`（在光标处拆行，光标不动）、`kill-line`（删到行尾，行尾时把
下一行接上来）、`next-line`、`prev-line`。门卫用小朋友能懂的理由拒绝：
`no-line`（没有那一行）、`too-far`（走太远）、`empty-buf`（缓冲区是空的）。

宿主（样例文件或 MiniMax）可以提议一个“命令助手”：返回一串命令的
Soft lambda。Soft 先查禁用词（`set!`、`display`、`eval`、`load`、`shell`、
`http` 等），再检查计划形状，然后和当前主助手在“hi / aura”两行目标上
比分。只有严格更高才 KEEP 并写入主缓冲区；相等或更低就 `heal!` 回滚并
DROP。样例：主助手 27，更差 14 DROP，平分 27 DROP，更好 31 KEEP。
