# M11 — Aura-unique features for kids

The ranked list in [`aura-vs-rust.md`](aura-vs-rust.md) Part 3 names the
features only Aura's live, transactional, attributable workspace AST makes
cheap. M11 builds them in order on the notebook stack (`ws.aura`,
`pen.aura`, `who.aura`, `who_pen.aura`). The play loop (`play.aura`) does
not load that stack, so key latency is unchanged (`smoke_perf.sh`). Soft
owns every decision; C only blits.

```bash
bash scripts/smoke_m11.sh    # PAD_M11_TEST_OK, PAD_M11_UNDO_OK, PAD_M11_WHO_OK (also run by smoke.sh)
```

Every API below was re-checked on Soft tip `c69e644` before use
(probes in `out/m11/p/`, not committed).

## M11a — "undo the robot" (`soft/pad/robot.aura`, `PAD_M11_UNDO_OK`)

**What the kid sees.** The helper proposes a change that touches several
defines (for example `hello` and `bye`). Either all of it lands or none
of it does. Afterwards **ctrl-z** (`IN 26`) takes the whole change back
in one key: both rows, the engine code and the "who wrote this" stamps.
A broken proposal never half-lands. The say line explains what happened:
"the helper changed hello and bye, ctrl-z takes it all back" or "aura
said no to the whole change, nothing moved".

**How.**
1. The Soft pen gate (`pad:pen-gate`) checks every edit first: kind
   words, locked words, `(lambda` only, a name born in the notebook, at
   most 4 edits, no name twice. A NO never takes a snapshot or calls the
   engine.
2. `ast:snapshot`, then **one** `typed-mutate-atomic` call with one
   `(mutate:rebind "name" "lam" "why")` sexpr per edit. The engine runs
   them under one MutationBoundary. `query:mutations-since` shows every
   record of the proposal with the same non-zero `composite=` id. The
   post-mutate typecheck runs too: arity errors are refused in every
   gate mode, type errors under `AURA_MUTATE_TYPE_GATE=hard`.
   `run_soft.sh` now passes that variable through, and `smoke_m11.sh`
   sets it to `hard`.
3. KEEP: every edited one-line define is projected into the page
   (`pad:pen-project`) and stamped `helper/why/gen`. The snapshot is
   pushed with the page.
4. ctrl-z: `ast:restore` plus one `eval-current` (aura#4349/#4361),
   then the page goes back too. Engine code and page must both equal the
   pre-proposal state, otherwise `M11_UNDO_DISAGREE` fails the smoke.
5. Refused: `ast:restore` plus `eval-current` anyway (a failed batch
   can leave stale node ids, #4361). The page is untouched and nothing
   is pushed.

**Measured on the tip.**
- A two-define KEEP bumps the workspace generation by 2 and the
  mutation total by 4.
- A refused proposal changes neither (`gen+=0 total+=0`). The good half
  of the proposal is absent from `query:code` (`A3_ADD_NOT_HALF`,
  `A3_HELLO_NOT_HALF`).
- Notebook procedures still answer after a refusal (`A3_CALLABLE`).

**Why not `mutate:atomic-batch`?** It returns a reason value, but on
`c69e644` it **skips the type and arity gate** in both modes: a batch
commits a rebind that `mutate:rebind` refuses. Filed as
[aura#4362](https://github.com/cybrid-systems/aura/issues/4362).
`typed-mutate-atomic` gates, but it answers only `#t` / `#f`, so M11c
recovers the kid reason separately.

**Not a transaction:** `ws:try-mutation` rolls back only when its body
*raises*. A refused `mutate:rebind` inside it returns a value, and an
earlier rebind in the same body stays committed (probe `p2`). The pad
does not use it.

## M11b — engine-level "who wrote this" (`soft/pad/eng_who.aura`, `PAD_M11_WHO_OK`)

**What the kid sees.** ctrl-o (`IN 15` on the notebook face,
`pad:robot-line!`) on a define row answers from aura's own log, not
from a pad guess: "the AI helper wrote hello: closer (change 2)", "a law
wrote greet: rule (change 6)", "the AI helper wrote hello, then you
changed it". Rows nobody changed, and rows that start no define, keep
the M10 answers ("nobody has changed this yet", "you wrote this line").

**How.**
1. Every robot transaction (M11a) and every pen step
   (`pad:ew-pen-step!`, which wraps M10's `pad:who-pen-step!`) runs
   under `mutate:set-agent-fingerprint`: kid=1, helper=42, macro=3,
   law=4. The fingerprint goes back to kid right after. The engine copies
   it onto every record of the transaction (`author=42` in
   `query:mutations-since`).
2. ctrl-o finds the define that starts on the cursor row (Soft tokens),
   then asks the engine:
   - `define-lookup name` gives the node id;
   - `query:node-provenance id` gives `author-fingerprint`,
     `mutation_id` and `gen` (`mutation_id` 0 means no write since the
     check);
   - the newest `op=rebind` record for that node in
     `query:mutations-since 0` gives the reason (`sum=`).
3. Cross-check with the M10 Soft stamp of the row:
   - `agree`: same writer and same reason, or no engine write while the
     Soft stamp is kid or none (kid typing reaches the engine at the
     next check);
   - `kid-after`: the engine writer wrote the define, then the kid typed
     on the row;
   - `soft-only`: the row starts no define (engine granularity is the
     define node);
   - `disagree`: anything else. It prints `M11_WHO_DISAGREE` and fails
     the smoke.
4. Undo needs nothing extra. `ast:restore` puts node provenance *and*
   the mutation log back to the snapshot. After a robot change by a
   helper and then one by a macro, the first ctrl-z leaves the helper's
   `add` at helper and returns the macro's `hello` to nobody (probe
   `p5`, test `B2`). The fingerprint is process state and is not
   restored, so the pad always sets it explicitly.

**Measured on the tip.**
- `EWHOROWS 0=hello:helper:agree.1=bye:helper:agree.2=add:nobody:agree.4=pet:nobody:agree.5=greet:law:agree`
  after a helper robot KEEP and a law pen KEEP.
- No `disagree` on any row across KEEP, two undos, and kid typing.
- The checker flags forged Soft stamps: wrong writer, wrong reason, a
  stamp missing where the engine has a write, and a stamp present where
  the engine has none (`B3_FORGED_*`).

**Limits.** The fingerprint is an integer label, not a principal
(aura#4037 in the source). Provenance is per define node, so the M10
Soft stamps still answer for rows that start no define.
