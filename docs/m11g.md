# M11g — the kid changes editor rules live

Part of [M11](m11.md). Marker `PAD_M11_RULES_OK`. Soft tip `c69e644`.

## M11g — the kid changes editor rules live (`soft/pad/kid_rules.aura`, `PAD_M11_RULES_OK`)

**What the kid sees.** The editor's own rules are lines on the page:

```scheme
(define (tab-size) 2)     ; how many spaces tab types
(define (say-max) 120)    ; how many letters the say line keeps
(define (indent n) (* n (tab-size)))
```

The kid types `tab 4` (the host sends `RULE tab 4`). Right away the
rule is live: tab types 4 spaces, `(indent 2)` is 8, and the row reads
`(define tab-size (lambda () 4))`. The say line answers:

> tab jumps 4 spaces now (was 2), indent uses it. ctrl-z puts it back

ctrl-z says "tab jumps 2 spaces again". ctrl-t / ctrl-n walk the rule
back and forth like any other step: "back to step 1 of 2: tab-size like
before your tab 4". ctrl-o on the row says "you wrote tab-size". A NO is
one kid sentence, and nothing moves:

| kid types | say line |
|-----------|----------|
| `tab 40`, `tab 0` | tab can jump 1 to 8 spaces |
| `tab lots`, `tab 2.5` | tab needs a number, like tab 1 |
| `jump 3` | there is no rule called jump, try tab or say |
| `tab 2` (already) | tab jumps 2 spaces already |
| `tab 3` on a page without the rule | this page has no tab rule yet |

`say 30` makes the say line keep 30 letters. The very next sentence is
cut: "there is no rule called jum...".

**How (Soft owns it, real APIs only).**
1. **Gate.** A Soft rule table holds the word, the define name, the
   range, the kid words and a thunk that calls the define. The kid's
   command must name a known rule, give one whole number, stay inside
   the range and differ from the live value. The define must be born in
   the engine (`define-lookup`), and aura must not be busy. A NO never
   snapshots or calls the engine.
2. **Write.** `ast:snapshot`, then one
   `typed-mutate-atomic ((mutate:rebind "tab-size" "(lambda () 4)" "tab 4"))`
   under author fingerprint kid=1 (`pad:ew-set!`, M11b). The kid's
   number is the only thing that goes into the body, so the kid cannot
   write code here.
3. **Keep.** `pad:robot-commit!` (M11a) projects the row, pushes the
   ctrl-z entry, stamps the row with who=kid, adds a time-machine step
   (M11e) and runs `typecheck-incremental`.
4. **Verify.** Soft calls the rule right after the KEEP, because it is
   live. If the value is outside the table's range, `pad:robot-undo!`
   takes the KEEP back at once (code, page, stamps and step): "the
   helper's tab-size gave 40, tab can jump 1 to 8 spaces, the old rule
   is back".
5. **Helpers.** A helper, macro or law proposes rule bodies with
   `pad:kr-propose!`. The pen gate applies (locked words, `(lambda`
   only), the name must be a rule, then the same write, keep and verify.
   Under `AURA_MUTATE_TYPE_GATE=hard`, `(lambda () "wide")` is refused by
   the engine: it blames the caller `(indent 2)`. The snapshot is healed
   and the kid reads "the helper's tab-size does not fit (indent 2), the
   old rule stays".
6. **Engine check.** Soft's "used by" (the call sites of the rule on the
   page) must equal `query:calls name`. It is taken before the
   transaction, because of aura#4364. A mismatch prints
   `M11_RULES_DISAGREE`.
7. **Effect.** `pad:kr-line!` is the notebook face with live rules:
   `IN 9` types `(tab-size)` spaces, and after every line the say line is
   cut to `(say-max)` letters. Everything else goes to `pad:robot-line!`.

**Measured on the tip** (targeted run `out/m11/g_only.txt`, 125 checks,
0 fail):
- `RULE verdict=KEEP word=tab name=tab-size value=4 used=1 eng=1`, and
  `query:node-provenance` author-fingerprint is 1 (`G1_FP`).
- ctrl-o `verdict=agree`. ctrl-z puts the code back byte for byte
  (`G1_UNDO_CODE`).
- `TIME from=2 to=1 eng=tab-size soft=tab-size code=yes verdict=agree`.
  Tab types 4 spaces, then 2 after ctrl-t (`G1_TAB_TYPES_4` /
  `G1_TAB_TYPES_2`).
- Every Soft NO: gen +0, code unchanged, no undo entry, strip unchanged
  (`G2_*`).
- `M11STATS ... rule_keeps=5 rule_refused=11 rule_dropped=1 rule_healed=1 rule_disagree=0`.

**Limits.**
- Two rules (tab, say) in a Soft table. A new rule needs a table row,
  plus a page define for it. A new define cannot be added by rebind
  (aura#4360), so the page must already have it.
- The rule thunks call the define through the shared top-level bindings.
  After a page without the rule is loaded, the last page's binding is
  still callable. `no-def` is decided by `define-lookup`, not by
  calling.
- Rules act on the notebook face only, at human speed. `play.aura` (the
  pad's own key path) does not read them, so key latency is unchanged.
  aura-vs-rust item 6 keeps live rule swaps off the hot key path
  (#4355 / #4357).
