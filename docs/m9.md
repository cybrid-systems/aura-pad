# M9: workspace notebook + pen

M9 makes the Aura workspace hold the kid's page, but only when the kid
asks for a **check**. A check (ctrl-s, byte 19) runs one `set-code` and one
`eval-current`. Typing stays on the M7 Soft line cache and never touches
the workspace. A **pen** (helper / macro / law) changes a define with
`mutate:rebind` inside the mutate boundary. The pen ends in REJECT, KEEP,
or DROP + `ast:restore` heal. Soft tip: `c69e644`.

```bash
bash scripts/smoke_m9.sh             # M9_ACC 1..6 OK, PAD_M9_TEST_OK, PAD_M9_OK
PAD_LIVE=0 bash scripts/smoke.sh     # M0..M9 → PAD_SMOKE_OK
```

## Notebook source

A check sends the page text followed by one data define:

```
(define (hello x) (+ x 1))
...
(define pad-nb-rows (list (list 40 100 101 ...) (list 59 32 107 ...) ...))
```

`query:code` returns a canonical `(begin ...)` and drops comments and
layout. The rows therefore come back from the `pad-nb-rows` data define
(char codes), never from re-printed page text. Char codes also avoid the
string-escape bug (#4348). The roundtrip load → project → load → project
is byte-equal for `"hi"` / `"  aura"` / `"pad"`, the 12-row page, and a
page with an empty row.

## Check (ctrl-s)

1. Guard (Soft only, no `set-code`): an unclosed `(` gives `open-paren`
   "close every ( before checking". Defining a pad-owned name (`pad…`,
   `pd:`, `*…`) gives `pad-name`.
2. `pad:ws-load!`: `set-code` must answer `#t`, then `eval-current`. Any
   other answer is a `fail`, because the workspace would still hold the
   old code. An unbound load surface goes on `GAPS` and the pad keeps
   editing the Soft buffer (`GAPS set-code` in the test).
3. Findings:
   - Soft names (find-defs pattern on HL tokens).
   - Engine names: every symbol candidate the engine says is born
     (`define-lookup`).
   - `missing` / `extra` both ways.
   - `query:defines` count, marks `name@row:col`.
   - `M9REFS` (`query:ref-counts` of each define node).
   - `M9NODES` (`query:node-types`).

```
M9CHECK reason=ok soft=hello.bye.add.pet.greet engine=hello.bye.add.pet.greet missing=none extra=none engine_total=6
M9MARKS hello@0:9.bye@1:9.add@2:9.pet@4:8.greet@5:9
M9LOAD ms=92 rows=12 src_len=239 note=aura#4343_aura#4350 soft_call_us_in_smoke_perf
M9REFS hello=1.bye=1.add=1.pet=1.greet=1
M9LOOKUP hello=line0:col0 note=aura#4347
```

Marks come from Soft tokens, because `define-lookup` line/col are always
0 today (#4347). `engine_total=6` counts the `pad-nb-rows` data define
too. One check of the 12-row page costs ~90 ms (one load, not one per
key). On every key that would be about 3× the M7 insert, so it stays a
check (#4343 / #4350).

## Pen

`pad:pen-step! who name lam why` returns `(verdict reason say gen+ total+)`:

- **REJECT** (no `set-code`, no generation bump, no undo push). Kid
  reasons:
  - `no-name` "tell me which name to change"
  - `not-kind` "let's use kind words"
  - `not-allowed` "that change uses a word the pad keeps locked"
  - `not-lambda` "a change has to start with (lambda"
  - `too-long` "that change is too big for one step"
  - `no-def` "could not find where that name is born"
  - `not-safe` "aura is busy, try again"
- **KEEP**: `ast:snapshot`, then `mutate:rebind` answers `#t`.
  - Generation +1 exactly; `mutate:summary :total` +2.
  - The one-line define row becomes `(define NAME LAM)` on the page.
  - Undo is `ast:restore` of that snapshot, plus the old page and cursor.
- **DROP** `engine-no` "aura could not use that change, page put back":
  the engine refused the rebind. `ast:restore` + one `eval-current` heal
  (#4349: closures are stale after a restore across a rebind until the
  workspace is re-evaluated). Heals are counted in `M9STATS heals=`.
  Nothing is called a "transaction".

```
KEEP pen who=helper name=hello reason=row gen+=1 total+=2 say="helper changed hello"
DROP pen who=helper name=bye reason=engine-no gen+=0 total+=0 say="aura could not use that change, page put back"
M9STATS set_code=11 eval=12 loads=10 checks=7 heals=2 keys=20 set_code_between_checks=0
```

The pen test page swaps the 12-row page's `(query:find hello)` row for
`(add 2 3)`. `query:*` is not bound inside the workspace, so
`mutate:rebind`'s post-mutate typecheck rejects every rebind on a page
that calls it. That is honest engine behaviour, so the pad does not hide
it.

## Honesty notes and Aura issues

| issue | what M9 does |
|-------|--------------|
| #4347 define-lookup line/col = 0 | Soft marks; `M9LOOKUP` prints the raw 0:0 |
| #4348 string literal loses a backslash | rows travel as char codes |
| #4349 stale closures after `ast:restore` past a rebind | heal = restore + one `eval-current`, counted |
| #4350 #4343/#4346 still linear, calls ~1.5× slower on `c69e644` | one load per check; numbers in `perf.md` |
| #4351 builtins resolve to pad globals when std is required late | `std.aura` loaded first; no requires inside `query.aura` |
| #4352 top-level named let in a loaded file breaks later prelude calls | no top-level named let in loaded files (`lc.aura` builds `*lc-cls*` with `pad:lc-cls-list`) |

Two more runner effects found while building M9. These are workarounds,
not filed:

- With the requires at the top of the file being run, a `mutate:rebind`
  or `set-code` made the runner re-run that whole file. The requires now
  live in `std.aura` (a loaded file), and the smoke fails if the test
  banner prints twice.
- Test sections are functions in `m9_cases.aura`, and the entry file
  makes one call, `(m9:run-all)`.

Not shipped: ctrl-s in `play.aura` (the C SNAP stream). `eval-current`
runs the page in the pad's Soft env, so the page's `display` output
(`cat` on the 12-row page) goes straight to stdout. Tip has no
`with-output-to-string`, so a check would corrupt the SNAP stream.
`pad:nb-line!` (IN 19 → check, everything else → `pad:play-line!`) is
tested in Soft, including 20 keys with zero `set-code` between checks.

## 中文

M9 让 Aura 工作区在小朋友按 ctrl-s「检查」时才接管页面：一次
`set-code` + 一次 `eval-current`，打字时零次（`M9STATS
set_code_between_checks=0`）。页面行以字符码数据 define 往返（`query:code`
会丢掉注释和排版，#4348 会吞反斜杠）。检查时比较引擎名字
（`define-lookup`）和 Soft 名字，打印缺少/多出、标记、引用数、节点类型；
12 行页面一次检查约 90 ms，所以只在检查时做。助手笔：REJECT 不写任何
东西（小朋友能懂的理由），KEEP 让 generation 恰好 +1 并改写那一行，
DROP 用 `ast:restore` + 一次 `eval-current` 修复（#4349）。这次新提的
Aura issue：#4347–#4352。play.aura 里还没接 ctrl-s：页面的 `display`
直接写到 stdout，tip 没有输出捕获，会弄坏 SNAP 流。
