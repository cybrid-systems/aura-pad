## M11h — intend self-repair loop (`soft/pad/fix_loop.aura`, `PAD_M11_FIX_OK`)

**What the kid sees.** The kid's goal is three checks (M11f). The helper
brings an idea and keeps fixing it until the checks pass, or until it
gives up. One line tells the story:

> the helper fixed it on try 3 (try 1: passes 2 of 3 checks | try 2: the helper's bye gives hello 2 things, it wants 1 | try 3: ok), kept it. ctrl-z takes it back

> the helper tried 3 times and never passed all 3 checks (best 0 of 3), nothing changed

The page does not move while the helper tries. Only a passing idea
comes back, as a normal robot KEEP: one ctrl-z, a who stamp
(`why=closer (try 3)`) and a time-machine step.

**How (Soft owns it, real APIs only).**
1. Soft calls `(intend goal gen verify fix max)` (aura tip). `gen` makes
   an idea; Soft copies its code/err with `string-append` before the next
   try (aura#4370: intend reuses string_heap slots).
2. The Soft verifier never `eval`s generated code (aura#4359). It opens a
   child world (`workspace :create` / `:switch`), applies the idea with
   `typed-mutate-atomic`, runs the goal checks there, heals root
   (`ast:restore` + `eval-current`, aura#4368), and answers in kid words.
3. Soft mirrors `intend-history` into a strip; any mismatch prints
   `M11_FIX_DISAGREE`.
4. A passing idea is KEPT by `pad:robot-step!` (M11a): one transaction,
   kid/helper fingerprint, ctrl-z, who, time-machine step.

**Measured** (H-only `out/m11/h_only.txt`, 35 checks, 0 fail):
- FIXED on try 3; strip matches Soft log; ctrl-z restores hello.
- GAVEUP leaves page/code unchanged; ALREADY short-circuits.

**Limits.** Same child-world keep rule as M11f (#4369). Notebook face
only; key latency unchanged.
